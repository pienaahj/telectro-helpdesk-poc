# Boschendal Customer Welcome Guide

## Main purpose

The Customer portal gives Boschendal customer users a simple way to:

- log support requests;
- identify the affected service area;
- choose the closest fault point or asset when known;
- attach photos or evidence;
- view progress;
- add more information when needed.

The Customer portal is not a formal sign-off system. Telectro confirms completion directly with the Customer through the normal service process and then resolves the ticket from the Telectro side.

---

## Customer portal

### Access

Customer portal:

`https://erp.telectro.co.za/helpdesk/my-tickets`

If you are not already signed in, you will be taken to the login page first.

Customer users should use:

`Support Requests`

---

## Basic customer workflow

1. Log in as a Customer user.
2. Open `Support Requests`.
3. Check whether the same issue is already logged.
4. Select `Log a Support Request` when this is a new issue.
5. Choose the relevant service area.
6. Choose the closest Fault Point or Fault Asset when one is known.
7. If the exact point is not available, leave it blank or choose the closest useful recognised point and explain the exact location in the description.
8. Add a short subject.
9. Add a clear description.
10. Attach photos, equipment labels, access notes, or evidence where helpful.
11. Submit the request.
12. Return to the ticket later to view progress or add more information.

If the issue is already logged, open the existing ticket and use `Add information` instead of creating a duplicate request.

## Important customer concepts

### Support Requests list

The `Support Requests` list shows support requests for the Customer organisation that the logged-in Customer user is permitted to access.

For Boschendal, authorised Boschendal Customer users may therefore see and participate in the same Boschendal support requests, even when another Boschendal user originally logged the ticket.

Each user should still log in with their own account so that updates and activity retain the correct user identity.

Use `Support Requests` to:

- check whether an issue is already logged;
- view ticket status;
- return to an existing request;
- read the latest visible update;
- add more information when needed.

### Log a Support Request

Use `Log a Support Request` when a new issue needs to be reported.

Before creating a new request, check `Support Requests` to make sure the same issue has not already been logged.

A good request includes:

- the relevant service area;
- the closest known Fault Point or Fault Asset, when one is available;
- a short, clear subject;
- a useful description of what is wrong and where;
- photos, equipment labels, access notes, or other evidence where helpful.

If the issue is already logged, open the existing ticket and use `Add information` instead.

### Fault Point

The Fault Point helps Telectro understand where the issue is located.

Choose the closest recognised Fault Point or Fault Asset when one is known and useful.

If the exact location is not available:

- choose a nearby recognised point only if it genuinely helps identify the location; or
- leave the Fault Point blank and describe the exact location clearly in the request.

Do not delay logging a valid support request because the exact Fault Point is not available.

The selected Fault Point or Fault Asset is a starting point for Telectro. The description should still explain where the problem is and include any useful room, building, equipment, access, or location details.

### Latest update

The `Latest update` card shows the most recent Customer-visible update from the ticket activity.

Use it to understand the latest progress, request for information, or outcome that Telectro has deliberately shared with the Customer.

Customers only see information intended for Customer visibility. Internal Telectro notes, routing details, assignment activity, and internal coordination are not shown in the Customer portal.

### Add information

Use `Add information` when more detail needs to be sent to Telectro after the ticket has already been created.

Use it for follow-up on the same issue instead of logging a duplicate request.

Useful examples include:

- additional symptoms;
- corrected location details;
- photos;
- equipment labels;
- access notes;
- contact availability;
- feedback after a Telectro update;
- a continuing concern after the ticket has been resolved.

If the problem is genuinely new or unrelated to the existing ticket, log a new support request instead.

### Evidence, photos, and visible updates

Customers can attach photos, equipment labels, access notes, screenshots, or other relevant evidence when:

- logging a support request; or
- adding follow-up information to an existing ticket.

Only attach information that is relevant to the support request and safe to place on the ticket.

Customer-submitted attachments are different from Telectro internal evidence.

Customers should expect to see:

- files they submitted through the Customer portal; and
- Telectro evidence that was deliberately shared through a Customer-visible update or resolution.

Customers should not expect every attachment held internally on the ticket to appear in the Customer portal.

Telectro may keep some evidence internal where it contains operational, technical, Partner, or other information that is not appropriate for Customer visibility.

If a Customer-visible update or resolution refers to evidence but the file is not available in the portal, use `Add information` on the same ticket and ask Telectro to confirm whether the evidence was shared.

## Customer do

- Use your own Customer account when logging in.
- Check `Support Requests` before logging a new issue.
- Use `Log a Support Request` for a genuinely new issue.
- Choose the closest recognised Fault Point or Fault Asset when one is known and useful.
- Describe the location clearly when the exact Fault Point is not available.
- Use a short, clear subject.
- Add enough detail for Telectro to understand what is wrong and where.
- Attach relevant photos, equipment labels, access notes, or other evidence where helpful.
- Use `Add information` for follow-up on an existing issue instead of logging a duplicate request.
- Read the latest Customer-visible update before adding follow-up information.
- Use `Add information` if the same concern continues after the ticket has been resolved.
- Check the ticket later for progress and outcome updates.

---

## Customer do not

- Do not share Customer login accounts.
- Do not log duplicate requests for the same issue unless there is a clear reason.
- Do not delay logging a valid request because the exact Fault Point is not available.
- Do not choose a random Fault Point simply to fill in the field.
- Do not attach passwords, unrelated documents, or information that is not needed for the support request.
- Do not expect every internal ticket attachment to be visible in the Customer portal.
- Do not expect to see Telectro internal notes, routing, assignment, or coordination activity.
- Do not use the Customer portal as a formal approval or sign-off process.
- Do not close tickets as part of the normal Customer workflow.
- Do not create a new ticket for follow-up on the same issue when `Add information` is appropriate.

---

## What done looks like for a Customer

Customer portal work is done when the Customer has completed the action that is needed from them.

This may mean:

- a new support request has been submitted with enough information for Telectro to start;
- requested follow-up information has been added to an existing ticket;
- relevant photos, equipment labels, access notes, or other evidence have been provided;
- the latest Customer-visible progress update has been reviewed;
- Telectro has resolved the ticket and the Customer has reviewed the visible outcome.

Formal Customer portal sign-off is not required before Telectro resolves or closes the ticket.

If the same concern continues after the ticket has been resolved, use `Add information` on the existing ticket and explain what is still wrong.

If the problem is genuinely new or unrelated, log a new support request.
